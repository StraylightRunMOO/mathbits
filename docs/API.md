# API.md — mathbits API Sketch (Comprehensive)

Self-contained, nauseatingly detailed illustration of the intended public API. All examples are mocked-up but follow the design in PLAN.md: hierarchical header-only C11, heavy preprocessor use in the style of [swizz.h](https://github.com/StraylightRunMOO/swizz.h) for type-safe fixed-size specializations, views by default, optional memento allocation, SIMD where it pays, and a later thin C++ facade aimed at common Eigen usage.

Consumers include only what they need. Fixed-size types and kernels are generated by macros so small operations become straight-line code that inlines and unrolls aggressively. Dynamic objects are non-owning views unless you explicitly allocate. Every multi-step or multi-output operation accepts caller-owned output views and optional scratch; there are no hidden allocations on hot paths.

## Preprocessor model for types (core flexibility)

Types are generated rather than hand-written. You configure once (or use the pre-generated common ones) and get a full set of operations.

```c
/* In a configuration header or before include — swizz.h style */
#define MATHBITS_DEFINE_VEC(N, T, SUFFIX)   /* generates vec##N##SUFFIX and all ops */
#define MATHBITS_DEFINE_MAT(R, C, T, SUFFIX)

/* Common ones are pre-generated for convenience */
MATHBITS_DEFINE_VEC(2, float, f)    /* vec2f */
MATHBITS_DEFINE_VEC(3, float, f)    /* vec3f */
MATHBITS_DEFINE_VEC(4, float, f)
MATHBITS_DEFINE_VEC(3, double, d)   /* vec3d */
MATHBITS_DEFINE_MAT(3, 3, float, f) /* mat3f */
MATHBITS_DEFINE_MAT(4, 4, float, f)
/* ... user can request more: MATHBITS_DEFINE_VEC(8, float, f) etc. */
```

Generated surface (illustrative for `vec3f`):

- Constructors: `vec3f_new`, `vec3f_zero`, `vec3f_one`, `vec3f_splat`
- Access: `.x/.y/.z` or macro swizzles (`VEC_XY(v)`, `VEC_YZ(v)`, etc.)
- Arithmetic: `vec3f_add`, `vec3f_sub`, `vec3f_mul`, `vec3f_scale`, `vec3f_neg`, `vec3f_mad`
- Reductions: `vec3f_dot`, `vec3f_norm`, `vec3f_norm_sq`, `vec3f_norm_inf`, `vec3f_sum`, `vec3f_min`, `vec3f_max`
- Geometry: `vec3f_cross`, `vec3f_normalize`, `vec3f_lerp`, `vec3f_reflect`, `vec3f_project`
- Comparison / selection: `vec3f_eq`, `vec3f_min`, `vec3f_max`, `vec3f_clamp`, `vec3f_select`
- All of the above have in-place variants where sensible (`vec3f_add_inplace`) and SIMD specializations when the width matches hardware.

The same pattern applies to matrices (`mat3f_mul`, `mat3f_transpose`, `mat3f_inverse`, `mat3f_mul_vec`, etc.). Dynamic `vec_f` / `mat_f` are views with explicit length/leading-dimension and the same operation names (minus the size).

## Vectors in depth (`vec.h`)

```c
/* Fixed-size construction and arithmetic */
vec3f a = vec3f_new(1.0f, 2.0f, 3.0f);
vec3f b = vec3f_splat(4.0f);
vec3f c = vec3f_add(a, b);
vec3f d = vec3f_mad(a, 2.0f, b);          /* a*2 + b */
vec3f n = vec3f_normalize(a);
float len = vec3f_norm(a);
float dot = vec3f_dot(a, b);
vec3f cr  = vec3f_cross(a, b);

/* Swizzles and component access */
vec2f xy = vec3f_xy(a);                   /* or macro VEC_XY(a) */
float z  = a.z;

/* In-place and reductions */
vec3f_scale_inplace(&a, 0.5f);
float sum = vec3f_sum(a);
float mn  = vec3f_min_element(a);

/* Dynamic view */
float buf[16];
vec_f v = vec_view(buf, 16);
vec_fill(&v, 1.0f);
vec_axpy(2.0f, &src, &v);                 /* v += 2*src */
float nrm = vec_norm(&v);

/* Stack-allocated owning fixed-size (no heap) */
vec4f local = vec4f_zero();
/* or */
MATHBITS_VEC_STACK(float, 8, tmp);        /* macro for aligned stack array + view */
```

Batch / SoA helpers (useful for lagrange-style particle or rigid-body loops):

```c
/* Structure-of-arrays view */
vec3f_batch pos = vec3f_batch_view(xs, ys, zs, n);
vec3f_batch_scale(&pos, dt);
```

## Matrices in depth (`mat.h`)

```c
/* Dynamic view */
float storage[12];
mat_f A = mat_view(storage, 3, 4, 4);     /* rows, cols, ld */
mat_set_identity(&A);                     /* only touches the leading square */
mat_set(&A, 1, 2, 3.14f);

/* Fixed-size */
mat3f R = mat3f_identity();
mat3f S = mat3f_scale(vec3f_new(2, 2, 2));
mat3f RS = mat3f_mul(R, S);
vec3f y = mat3f_mul_vec(RS, x);

/* gemv / gemm with explicit output (no temporary) */
vec_f yout = vec_view(outbuf, 3);
mat_gemv(1.0f, &A, &x, 0.0f, &yout);      /* yout = 1*A*x + 0*yout */

mat_f C = mat_view(cbuf, 4, 4, 4);
mat_gemm(1.0f, &A, &B, 0.0f, &C);

/* Views of blocks, rows, columns, diagonals */
mat_f block = mat_block(&A, 1, 1, 2, 2);
vec_f row0  = mat_row(&A, 0);
vec_f diag  = mat_diagonal(&A);

/* Transpose is a view (no copy) when strides allow */
mat_f AT = mat_transpose_view(&A);

/* Element-wise */
mat_add_inplace(&A, &B);
mat_scale_inplace(&A, 0.5f);
mat_mul_elementwise(&A, &B, &C);
```

### Avoiding intermediate allocations (patterns)

```c
/* Residual norm without materializing A*x - b */
float rn = mat_gemv_residual_norm(&A, &x, &b);

/* Fused multiply-add into existing storage */
mat_gemm(1.0f, &A, &B, 1.0f, &C);         /* C += A*B */

/* Scratch from stack or arena for blocked algorithms */
float scratch[256];
mat_f work = mat_view(scratch, 16, 16, 16);
linalg_qr_overwrite(&A, &work);           /* or any routine that needs workspace */

/* Chained operation writing into one buffer */
mat_f tmp = mat_view(arena_alloc(...), m, n, n);
/* step 1 writes tmp, step 2 reads tmp and writes final */
```

Norms and trace:

```c
float tr  = mat_trace(&A);
float fro = mat_norm_frobenius(&A);
float inf = mat_norm_inf(&A);
float op  = mat_norm_1(&A);               /* or operator-norm estimate */
```

## Factorizations, solvers, and decompositions (`linalg.h`)

```c
/* Tiny fixed-size — fully unrolled, no loops */
mat2f A2 = mat2f_new(/* ... */);
mat2f A2inv;
bool ok = mat2f_inverse(&A2, &A2inv);
float det = mat2f_determinant(&A2);

mat3f A3 = /* ... */;
mat3f A3inv;
mat3f_inverse(&A3, &A3inv);               /* or mat3f_inverse_inplace */

/* Cholesky (A must be SPD) */
mat_f L = mat_alloc(n, n);                /* or view */
bool spd = linalg_cholesky(&A, &L);       /* A = L L^T */

/* QR */
mat_f Q = mat_alloc(m, n);
mat_f R = mat_alloc(n, n);
linalg_qr(&A, &Q, &R);

/* SVD — thin or full */
mat_f U, S, Vt;
linalg_svd(&A, &U, &S, &Vt);              /* optional ComputeThinU flag style */

/* Eigendecomposition for symmetric */
vec_f evals;
mat_f evecs;
linalg_syev(&A, &evals, &evecs);

/* Least squares and regression */
vec_f beta = vec_alloc(n);
linalg_lstsq(&X, &y, &beta);              /* min ||X beta - y|| */
linalg_ols(&X, &y, &beta);                /* same, with optional intercept */
linalg_ridge(&X, &y, 1e-3f, &beta);

/* Solve triangular or general */
linalg_solve_triangular(&L, &b, &x, true /* lower */);
linalg_solve(&A, &b, &x);                 /* LU or QR under the hood */
```

All routines accept pre-allocated outputs and an optional workspace view. For large N an optional compile-time CBLAS/LAPACK backend can be enabled; the default path never requires it.

## Sparse (`mat/sparse.h`)

#include "mathbits/mat/sparse.h"

/* Conversion */

sparse_mat_f back = sparse_from_dense(&dense, 1e-8f /* drop tol */);

## Adjacency and transition (`mat/adjacency.h`, `mat/transition.h`)

```c
#include "mathbits/mat/adjacency.h"
#include "mathbits/mat/transition.h"

/* From edge list (undirected or directed) */
uint32_t edges[][2] = { {0,1}, {1,2}, {2,0} };

mat_f dense = adjacency_to_dense(&Adj);
sparse_mat_f sp = adjacency_to_sparse(&Adj);

/* Row-stochastic transition matrix */

/* or column-stochastic, or from a rate matrix, etc. */

```

## PCA, regression, and statistics-style ops

```c
/* Center columns in-place or into output */
mat_f Xc = mat_alloc(n_samples, n_features);
mat_center_columns(&X, &Xc);

/* PCA */
mat_f components;   /* n_features × k */
vec_f explained_var;
linalg_pca(&Xc, k, &components, &explained_var);

/* Project */
mat_f scores = mat_alloc(n_samples, k);
mat_gemm(1.0f, &Xc, &components, 0.0f, &scores);

/* Covariance */
mat_f cov = mat_alloc(n_features, n_features);
linalg_covariance(&Xc, &cov);             /* or with Bessel correction flag */
```

## Neural nets (`nn.h`)

```c
#include "mathbits/nn.h"

/* Layer table */
nn_layer_t layers[] = {
    nn_dense(16, 64, w0, b0, NN_RELU),
    nn_dense(64, 32, w1, b1, NN_GELU),
    nn_dense(32,  8, w2, b2, NN_NONE),    /* e.g. landmark offsets */
};
nn_sequential_t net = nn_sequential(layers, 3);

/* Forward — activations written into caller-supplied or arena storage */
vec_f in  = vec_view(features, 16);
vec_f out = vec_alloc(8);
nn_workspace_t ws = nn_workspace_alloc(&net);   /* or from memento */
nn_forward(&net, &in, &out, &ws);

/* Batched */
mat_f batch_in  = mat_view(/* n_batch × 16 */);
mat_f batch_out = mat_alloc(n_batch, 8);
nn_forward_batch(&net, &batch_in, &batch_out, &ws);
```

Weight loading:

```c
/* From flat blob or C array generated by a Python exporter */

```

## Geometry and transforms (`geometry.h`) — lagrange extraction target

```c
#include "mathbits/geometry.h"

/* Quaternions */
quat_f q = quat_from_axis_angle(vec3f_new(0,1,0), 1.5708f);
quat_f qid = quat_identity();
vec3f rotated = quat_rotate(q, v);
quat_f qmul = quat_mul(q1, q2);
quat_f qn = quat_normalize(q);

/* Rigid transform (translation + rotation) */
rigid_f T = rigid_from_translation_rotation(pos, q);
vec3f world = rigid_transform_point(T, local);
vec3f dir   = rigid_transform_vector(T, local_dir);  /* no translation */

/* Compose, invert */
rigid_f Tinv = rigid_inverse(T);
rigid_f Tcomp = rigid_mul(T2, T1);

/* Bounding volumes */
aabb_f box = aabb_from_points(pts, n);
bool hit = aabb_intersects(&box, &other);
sphere_f s = sphere_new(center, radius);
```

These match the style of lagrange’s `math.h` / `transform.h` so the physics library can later sit on top of mathbits.

## DSP / Fourier integration

mathbits supplies the views; the actual transform stays in Notorious-FFT (or another library).

```c
#include "mathbits/vec.h"
/* #include "notorious_fft.h"  — external */

vec_f signal = vec_view(samples, n);
/* User calls Notorious-FFT planner/executor on signal.data / signal.n */

/* Optional thin helpers */
void mathbits_rfft_forward(vec_f *inout, void *plan);   /* bridge example */
void mathbits_convolve(const vec_f *a, const vec_f *b, vec_f *out);
```

Spectral helpers that are pure mathbits (no FFT required):

```c
vec_f power = vec_alloc(n/2);
mathbits_periodogram(&signal, &power);   /* or magnitude-squared of user-supplied FFT */
```

## Eigen-style C++ facade (detailed sketch)

Zero-overhead wrappers. Fixed-size types are templates over the macro-generated C objects. Expressions that would create temporaries in naive code are either elided by the wrappers or documented as writing into caller storage. Owning containers use RAII; `Map` never allocates.

```cpp
#include "mathbits/eigen_compat.hpp"
using namespace mathbits;

// Fixed-size — identical feel to Eigen
Vector3f a(1.0f, 2.0f, 3.0f);
Vector3f b(4.0f, 5.0f, 6.0f);
Vector3f c = a + b * 2.0f;
Vector3f n = a.normalized();
float d = a.dot(b);
Vector3f cr = a.cross(b);

Matrix3f R = Matrix3f::Identity();
Matrix3f S = Matrix3f::Scaling(2.0f, 2.0f, 2.0f);
Matrix3f RS = R * S;
Vector3f y = RS * a;

// Dynamic owning
MatrixXf A(3, 4);
A.setIdentity();                 // on the square part
A(1, 2) = 3.14f;

// Non-owning Map (Eigen-compatible)
float raw[12];
Map<MatrixXf> Am(raw, 3, 4);

// Blocks, rows, cols
auto blk = A.block(0, 0, 2, 2);
auto row = A.row(0);
auto col = A.col(1);

// Factorizations
JacobiSVD<MatrixXf> svd(A, ComputeThinU | ComputeThinV);
VectorXf sing = svd.singularValues();

// Or the native path
auto [U, S, Vt] = linalg::svd(A);   // structured binding helper

// Least squares
VectorXf x = A.colPivHouseholderQr().solve(b);
// or
VectorXf beta = linalg::lstsq(X, y);

// No-allocation style (explicit output)
VectorXf out(3);
A.mul(x, out);                   // out = A * x
// or gemm into existing
C.noalias() += A * B;            // mapped to the C gemm with beta=1

// Geometry
Quaternionf q = Quaternionf::FromTwoVectors(a, b);
Vector3f rotated = q * v;
Isometry3f T = Isometry3f::Identity();
T.translate(Vector3f(1,0,0)).rotate(q);
Vector3f world = T * local;

// NN
Sequential net = { Dense(16,32,ReLU), Dense(32,8) };
VectorXf pred = net.forward(input);
```

The C++ layer never allocates on the paths that the C API can do without allocation. Fixed-size operations compile down to the same unrolled/SIMD kernels as the C versions.

## Summary of allocation and performance contract

- Views (`vec_view`, `mat_view`, `Map<>`) never allocate.
- `*_alloc` functions use the current allocator (memento or malloc).
- Multi-step algorithms (QR, SVD, PCA, NN forward, integrators) write into caller-supplied outputs and optional scratch.
- Fixed-size macro-generated types (`vec3f`, `mat4f`, etc.) are POD, stack-friendly, and expected to match or beat Eigen on those sizes because the specialization is exact and there is no expression-template machinery.
- Dynamic medium-size gemm/gemv use hand-written or lightly blocked SIMD kernels; very large sizes can optionally dispatch to an external BLAS.
- The entire surface is usable from pure C11. The C++ facade is additive.

This API covers the needs of the boat-landmark / category-classifier pipeline, the generic numeric pieces that can be extracted from lagrange, small-network inference, geometry, optimization, sparse graph matrices, sampling, and the hierarchical extension model, while staying consistent with the header-only, preprocessor-driven, memento-optional style of the surrounding ecosystem.
